# 09 — MSSQL → PostgreSQL Mapping

> **Good news up front:** the type conversion is close to mechanical. All 40 money
> and quantity columns are proper `numeric(18,2)` — no float, no `money`, no
> money-as-string. All 40 temporal columns are proper date/datetime types — no
> dates stored as strings. No XML columns. No computed columns in the model.
>
> **The difficulty is not the types. It is the ~62 reference columns with no
> foreign key**, which PostgreSQL will refuse to constrain until the orphans are
> cleaned. That census is the gating unknown.

---

## 1. Type mapping table

| MSSQL type (as configured) | Columns | PostgreSQL | Risk | Conversion note |
|---|---:|---|---|---|
| `nvarchar(n)` | 101 | `varchar(n)` | Low | PostgreSQL is Unicode natively; the `n` prefix is meaningless. **Check collation** — see §4 |
| `uniqueidentifier` | 70 | `uuid` | Low | Values are **client-generated** (`Guid.NewGuid()` at 19 sites). Only `User.Id` has a `(newid())` default, which the app overrides anyway |
| `numeric(18,2)` | 40 | `numeric(18,2)` | **None** | Direct. Widen rate columns — see §3 |
| `int` | 39 | `integer` | Low | 10 are IDENTITY → `GENERATED BY DEFAULT AS IDENTITY`, then `setval()` after load |
| `bit` | 32 | `boolean` | **Medium** | 22 are **nullable**. Backfill `NULL → false`, then `SET NOT NULL`. See §5 |
| `datetime` | 32 | `timestamp(3)` | Low | `datetime` has ~3.33 ms resolution; `timestamp(3)` is a faithful superset. Consider `timestamptz` — see §4 |
| `nvarchar(max)` | 11 | `text` | Low | Several should be **bounded** instead — see §3 |
| `date` | 8 | `date` | Low | Direct |
| `char(2)` | 1 | `char(2)` | Low | ⚠️ Blank-padding semantics differ. Prefer `varchar(2)` |
| `varchar(n)` | 3 | `varchar(n)` | Low | Non-Unicode source; check for stray high-byte characters |

**Totals:** 337 columns, 24 tables.

| SQL Server feature | Used here? | PostgreSQL equivalent |
|---|---|---|
| `uniqueidentifier` / `NEWID()` | Yes, 70 cols | `uuid` / `gen_random_uuid()` (pgcrypto, built in since PG 13) |
| `IDENTITY(1,1)` | 10 columns | `GENERATED BY DEFAULT AS IDENTITY`. **`setval()` required after bulk load** |
| `datetime` / `datetime2` | 32 columns | `timestamp(3)` / `timestamptz` |
| `bit` | 32 columns | `boolean` |
| `nvarchar` | 101 columns | `varchar` (PostgreSQL is Unicode by default) |
| `money` | **Not used** | — |
| `xml` | **Not used** | — |
| `GETDATE()` default | **UNKNOWN — requires live DB** | `now()` |
| Computed columns | **UNKNOWN** — `PurchaseOrderDetail.ItemTotal` is a candidate | `GENERATED ALWAYS AS (…) STORED`. ⚠️ **Verify stored values match the formula first** — mismatches indicate historical data the generated column would silently change |
| `TOP n` | via LINQ | `LIMIT n` |
| `OFFSET/FETCH` | Not used (no paging!) | `LIMIT`/`OFFSET`, or better **keyset pagination** |
| `ISNULL` | in LINQ | `COALESCE` |
| `LEN` | in LINQ | `length()` |
| `GETUTCDATE` | | `now() AT TIME ZONE 'utc'` |
| `STRING_SPLIT` | Would be needed for `User.SiteId` | `string_to_array` + `unnest` — **used once, in the migration, then never again** |
| Case-insensitive default collation | Likely | `citext`, or `lower()` functional indexes. **See §4 — this is a real behaviour change** |
| Stored procedures | **UNKNOWN** — ~440 lines of commented-out calls exist | PL/pgSQL functions, or move the logic to the application (**preferred**) |
| Triggers | **UNKNOWN** | PL/pgSQL triggers. Prefer application-level logic |
| Full-text search | **UNKNOWN** | `tsvector` + GIN, or `pg_trgm` for fuzzy matching |
| `MERGE` | Not used | `INSERT … ON CONFLICT DO UPDATE` |
| Row versioning / `rowversion` | Not used | **`xmin` system column** via `UseXminAsConcurrencyToken()` — free optimistic concurrency |
| Filtered indexes | **UNKNOWN** | Partial indexes — `CREATE INDEX … WHERE is_deleted = false` |
| Included columns | **UNKNOWN** | `INCLUDE (…)` — supported since PG 11 |

## 3. Type decisions to make deliberately

These are places where a straight copy would perpetuate a defect.

| Column(s) | Current | Recommended | Why |
|---|---|---|---|
| `GSTPer`, `DiscountPer` | `numeric(18,2)` | **`numeric(9,4)`** | 2 decimal places cannot represent a rate like 18.5% stored as 0.185 |
| `Quantity` (most tables) | `numeric(18,2)` | `numeric(18,3)` | Three decimals for weight/volume units |
| `PodeliveryAddress.Quantity` | **`int`** | `numeric(18,3)` | Inconsistent with every other Quantity in the schema |
| `PurchaseOrderDetail.ItemName` | `varchar(50)` | **`varchar(100)`** | ⚠️ **Truncates against `ItemMaster.ItemName varchar(100)`** — live data loss |
| `SupplierInvoiceDetail.ItemName` | `varchar(50)` | `varchar(100)` | Same |
| `SupplierMaster.SupplierName` | **`varchar(30)`** | `varchar(200)` | 30 characters is not enough for a legal entity name |
| `User.Password` | `varchar(20)` | **`varchar(255)`**, renamed `password_hash` | Too small for any hash. Also caps passwords at 20 chars |
| `User.Email` | `varchar(40)` | `varchar(255)` | |
| `Company.GSTNo` | `varchar(17)` | `varchar(15)` | Indian GSTIN is exactly 15 characters. Supplier's is `varchar(20)` — normalise both |

| `ItemInword.DocumentName` | `nvarchar(max)` | `varchar(260)` | |
| `PurchaseOrder.Terms`, `.PaymentTerms` | `nvarchar(max)` | `text` | Genuinely unbounded — fine |
| `ItemInword.Date` | `datetime` | `date` | ⚠️ 7 peer tables use `date`. **Verify the time component is unused first** |
| 22 nullable `bit` columns | `bit NULL` | `boolean NOT NULL DEFAULT false` | See §5 |

## 4. Two decisions that change behaviour

### 4.1 Collation and case sensitivity

SQL Server databases commonly default to a **case-insensitive** collation
(`SQL_Latin1_General_CP1_CI_AS`). PostgreSQL is **case-sensitive by default**.

If that is the case here — **UNKNOWN, resolved by §0 of the schema extraction
script** — then a login that works today as `Admin` will fail as `admin` after
migration, and searches will stop matching.

**Options, per column:**

| Approach | Use for |
|---|---|
| `citext` extension | `user_name`, `email` — natural identity columns |
| `lower()` functional index + `lower()` in queries | search columns |
| ICU non-deterministic collation (`PG 12+`) | when you need it schema-wide |
| Leave case-sensitive | document numbers, codes — where exactness is correct |

**Highest-risk columns:** `user_name`, `email`, `item_name`, and every `*_no`
document number (which is also matched **by string equality** for PO↔Invoice —
see [07, D10](07-Business-Rule-Inventory.md)).

### 4.2 `timestamp` vs `timestamptz`

The application uses `DateTime.Now` (local server time) throughout, including for
JWT expiry — where it causes a real bug. The database columns are `datetime`,
which carries no zone.

**Recommendation:** use `timestamptz` for **audit** columns (`created_on`,
`updated_on`) and store UTC. Use `date` for **business dates** (invoice date,
PO date) — a GST invoice date is a calendar date, not an instant, and must not
shift across zones.

**Migration:** existing `datetime` values are IST wall-clock. Convert to UTC on
load with an explicit `AT TIME ZONE 'Asia/Kolkata'`. **Do not let the driver guess.**

## 5. The nullable booleans — a behaviour change with business impact

22 `bit` columns are nullable. The application filters `IsDeleted == false`.

**A row where `IsDeleted IS NULL` is therefore invisible to users today.**

Backfilling `NULL → false` — which the target schema requires — will make those
rows **appear**. That is arguably a bug fix, but it is a visible change to what
users see.

**Process:**
1. Run Part G of the census script to count them.
2. Show the business what would become visible.
3. Get sign-off before backfilling.
4. Record the before/after counts in the migration log.

## 6. Naming convention

**Recommendation: `snake_case` throughout.**

PostgreSQL folds unquoted identifiers to lowercase. Keeping `PascalCase` means every
identifier must be `"double-quoted"` forever, in every query, in every tool, by
every developer. That is a permanent tax for a one-time rename.

| MSSQL | PostgreSQL |
|---|---|
| `SupplierInvoice` | `supplier_invoice` |
| `SupplierInvoiceDetails` | `supplier_invoice_detail` (singular — consistent) |
| `User` | **`app_user`** ⚠️ `user` is a PostgreSQL reserved word |
| `ItemInword` | `item_inward` (fix the spelling while renaming) |
| `PODelevryAddress` | `po_delivery_address` |
| `ContectPersonName` | `contact_person_name` |
| `IFFCCode` | `ifsc_code` |
| `IsDelete` / `IsDeleted` | `is_deleted` (normalise both) |
| `Createdby` | `created_by` |

Drizzle maps `snake_case` columns to `camelCase` TypeScript properties cleanly, so
the application code stays idiomatic.

## 7. Structural changes required (not optional)

These are cases where a faithful copy would carry a defect into the new system.

### 7.1 `User.SiteId` / `User.CompanyId` → junction tables

The single highest-value schema change. Two `nvarchar(max)` comma-separated GUID
lists currently drive authorisation.

```sql
CREATE TABLE user_site (
    user_id    uuid    NOT NULL REFERENCES app_user(id)  ON DELETE CASCADE,
    site_id    uuid    NOT NULL REFERENCES site(site_id)  ON DELETE RESTRICT,
    is_deleted boolean NOT NULL DEFAULT false,
    created_by uuid    REFERENCES app_user(id),
    created_on timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (user_id, site_id)
);
CREATE INDEX ix_user_site_site ON user_site (site_id);

CREATE TABLE user_company (
    user_id    uuid    NOT NULL REFERENCES app_user(id)       ON DELETE CASCADE,
    company_id uuid    NOT NULL REFERENCES company(company_id) ON DELETE RESTRICT,
    is_deleted boolean NOT NULL DEFAULT false,
    created_by uuid    REFERENCES app_user(id),
    created_on timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (user_id, company_id)
);
```

**Backfill:**
```sql
INSERT INTO user_site (user_id, site_id)
SELECT u.id, s.guid
FROM   legacy_user u
CROSS JOIN LATERAL unnest(string_to_array(u.site_id, ',')) AS raw(txt)
CROSS JOIN LATERAL (SELECT NULLIF(btrim(raw.txt), '')::uuid AS guid) s
WHERE  u.site_id IS NOT NULL
  AND  btrim(raw.txt) <> ''
  AND  EXISTS (SELECT 1 FROM site x WHERE x.site_id = s.guid)
ON CONFLICT DO NOTHING;
```
The `EXISTS` guard reproduces the behaviour of `UserAuthentication.cs:57`, which
silently discards unparseable entries. **Log the discarded rows** — they represent
access grants that were already silently broken.

⚠️ **This is a coordinated code + data change**, not a schema-only one. The
authorisation code must change at the same moment.

### 7.2 Document-number sentinels → a `document_type` discriminator

`SupplierInvoice.InvoiceNo` holds `'PayOut'` and `'Opening Balance'`;
`SalesInvoice.SalesInvoiceNo` holds `'PayIn'`. These will **break any unique
constraint**.

```sql
CREATE TYPE document_type_t AS ENUM ('invoice','payment','opening_balance','purchase_return','credit_note');

ALTER TABLE supplier_invoice ADD COLUMN document_type document_type_t NOT NULL DEFAULT 'invoice';
UPDATE supplier_invoice SET document_type = 'payment'         WHERE invoice_no = 'PayOut';
UPDATE supplier_invoice SET document_type = 'opening_balance' WHERE invoice_no = 'Opening Balance';
UPDATE supplier_invoice SET invoice_no = NULL WHERE document_type <> 'invoice';

CREATE UNIQUE INDEX uq_supplier_invoice_no
  ON supplier_invoice (company_id, invoice_no)
  WHERE document_type = 'invoice' AND is_deleted = false;
```

Better still: move payments into their own `payment` table. That is a **model
change**, so put the question to the business — but it is the correct end state.

### 7.3 Document numbering → sequences

Replaces the racy read-max-then-increment of [07, D1-D4](07-Business-Rule-Inventory.md):

```sql
CREATE TABLE document_counter (
    company_id     uuid        NOT NULL REFERENCES company(company_id),
    document_kind  text        NOT NULL,           -- 'invoice' | 'po' | 'pr' | 'sales'
    financial_year text        NOT NULL,           -- '24-25'
    next_value     integer     NOT NULL DEFAULT 1,
    PRIMARY KEY (company_id, document_kind, financial_year)
);
```

Allocation, atomic and race-free:
```sql
INSERT INTO document_counter (company_id, document_kind, financial_year, next_value)
VALUES ($1, $2, $3, 2)
ON CONFLICT (company_id, document_kind, financial_year)
DO UPDATE SET next_value = document_counter.next_value + 1
RETURNING next_value - 1 AS allocated;
```
Run inside the same transaction as the insert. Combined with the unique index in
§7.2, duplicate invoice numbers become **impossible** rather than merely unlikely.

⚠️ **Seeding:** initialise `next_value` from `MAX(existing) + 1` per
(company, kind, FY) during migration, and **widen the format from `D3` to `D4` or
`D5`** so the sequence does not wrap at 999.

### 7.4 The four master/detail foreign keys

```sql
ALTER TABLE purchase_order_detail
  ADD CONSTRAINT fk_pod_purchase_order
  FOREIGN KEY (purchase_order_id) REFERENCES purchase_order(id) ON DELETE CASCADE NOT VALID;
-- after the orphan census and remediation:
ALTER TABLE purchase_order_detail VALIDATE CONSTRAINT fk_pod_purchase_order;
```

`NOT VALID` takes only a brief lock; `VALIDATE CONSTRAINT` then scans without
blocking writes. Essential for `app_user`'s self-reference and the 30 audit FKs.

### 7.5 `SupplierInvoice.POId` (text) → `purchase_order_id uuid`

Currently a `nvarchar(100)` string match. To convert:
```sql
UPDATE supplier_invoice si
SET    purchase_order_id = po.id
FROM   purchase_order po
WHERE  btrim(upper(si.po_id_legacy)) = btrim(upper(po.po_number));
```
Expect **partial matches**. Quarantine the rest and leave `purchase_order_id` NULL.
Report the unmatched count to the business — those are POs whose invoices the system
currently believes are unfulfilled.

## 9. Cross-cutting migration steps

Apply once, in this order.

| # | Step | Note |
|---|---|---|
| **1** | **Re-scaffold the EF model against the live DB and diff it** | Three clues in the current model (`PK_Users` on table `User`, `PK_Form_1`, `PK_PODelevryAddress`) prove the schema has been renamed and recreated over time. **Any drift invalidates parts of this analysis** |
| **2** | Run the three extraction scripts | Indexes, constraints, triggers, procs, row counts, collation |
| **3** | **Orphan census** (script 03, Parts A-C) | **The single biggest determinant of the timeline.** Every non-zero result is remediation work |
| **4** | **Duplicate census** (Part D) | Every proposed unique constraint must pass first. The `'PayIn'` rows are a known guaranteed failure |
| **5** | **NULL boolean backfill** (Part G) | Behaviour change — needs business sign-off |
| **6** | **Money reconciliation** (Part H) | After backfilling NULL money to 0, re-check header-vs-line totals. Divergence means the NULLs were masking real problems |
| **7** | Collation decision | Per column. Affects all 116 string columns |
| **8** | Load data, then `setval()` all 10 identity sequences | Skipping this breaks the first insert on each table |
| **9** | Add FKs `NOT VALID`, then `VALIDATE` | Brief lock, then a non-blocking scan |
| **10** | Enable `xmin` concurrency on all mutable entities | Free on PostgreSQL, closes the concurrency gap at zero storage cost |
| **11** | Delete the dead code | `DbHelper.cs` (uses `SqlConnection`, will not compile against Npgsql), the 5 commented-out proc call sites, the 4 unmapped entity classes, `ItemInWordRepo.cs` |

## 10. Tooling

| Task | Recommended | Note |
|---|---|---|
| Schema conversion | **Hand-written DDL** | ⚠️ **Do not use `pgloader` or an automated converter for the schema.** They faithfully reproduce the defects — the CSV columns, the missing FKs, the overloaded document-number columns. The schema needs deliberate redesign, and it is only 24 tables |
| Bulk data load | `pgloader`, **or** custom ETL | For a schema this size, a custom Node/Python ETL gives the control needed for the type and structural changes. `pgloader` is fine for the straightforward reference tables |
| Migrations | **Drizzle Kit** | Versioned SQL migrations, checked into source control |
| Verification | Custom reconciliation harness | See [14-Data-Migration-and-Testing.md](14-Data-Migration-and-Testing.md) |
| Ongoing sync during parallel run | **Debezium CDC**, or a timestamp-based delta job | Depends on the cutover strategy chosen |
